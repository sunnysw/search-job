# AI/AX 강사·컨설턴트 구인 트래커 설계서

Google Sheets + Google Apps Script(clasp)로 구인 공고를 수집·정리하고 지원 현황을 관리한다.

## 1. 목표

- AI/AX 관련 **강사·컨설턴트 공고**를 자동 수집해 한 목록에 모은다 (+ 수동 입력).
- 공고별 **지원 상태**를 추적한다 (관심 → 지원 → 서류/면접 → 결과, 보류/패스 사유 기록).
- **마감 임박**과 **신규 공고**를 매일 아침 Gmail로 요약 받는다.

## 2. 대상 공고 유형

| 코드 | 유형 | 예시 |
|---|---|---|
| `채용-강사` | 정규/계약 강사 채용 | 교육기관·기업 소속 AI/AX 강사 |
| `의뢰-강의` | 프리랜서 강의 의뢰 | 기업 출강, 강사 풀 모집 |
| `채용-컨설턴트` | 컨설턴트 채용/프로젝트 | AX 전환 컨설팅, 프로젝트 계약 |
| `공공-강사멘토` | 정부/공공 사업 강사·멘토 | 나라장터, K-Startup, 지자체·진흥원 |

## 3. 전체 구조

```
[수집원]                      [Apps Script]                    [Google Sheet]
 Google 알리미 RSS ─┐
 사람인/잡코리아/원티드 ─┤  collect() ─ 정규화 ─ 필터 ─ 중복제거 ─▶  01_전체관리 (미검토)
 나라장터/K-Startup API ─┤        (매일/수시 트리거)
 프리랜서 플랫폼 ───────┤
 수동 입력(URL 붙여넣기) ─┘  onEdit() ─ 상태 변경 로그 ─────────▶  이력
                             dailyDigest() ─ Gmail 요약 발송
```

### 수집 방식 (스크래핑 제약 대응)
사이트별로 차단/약관 이슈가 달라 **안정적인 순서**로 구현한다.

1. **Google 알리미 RSS** (키워드별 피드 URL을 `수집원` 시트에 등록) — 모든 사이트 공통 보조 채널
2. **공공데이터 OpenAPI** (나라장터 입찰공고, K-Startup 사업공고) — 공식 API라 안정적
3. **사람인 / 잡코리아 / 원티드** — 공식 오픈 API 또는 검색결과 RSS/알림메일 파싱을 우선. HTML 스크래핑은 `UrlFetchApp`로 시도하되 차단 시 건너뛰고 오류를 `로그`에 남김
4. **프리랜서 플랫폼**(탈잉·클래스101·크몽·숨고 등) — 공개 모집 페이지/알림메일 기반, 사이트별 파서 모듈
5. **수동 입력** — `01_전체관리`에 URL만 붙여넣으면 `onEdit`이 제목/마감일 추출 시도 후 나머지는 직접 입력

> 각 소스는 `sources/<name>.gs`의 독립 어댑터이며 동일 형식 `{title, org, url, postedAt, deadline, type, raw}`을 반환한다. 하나가 실패해도 나머지는 계속 실행된다.

## 4. 시트 구성

참고 시트(`DX_AX_AI_모집공고_관리`)의 구조가 이미 잘 정리되어 있어, **탭 분리 원칙(감시 트랙 / 실제 공고 / 분류체계 / 지원관리 / 기관 / 가이드)** 을 계승하고 자동화에 필요한 탭만 추가한다.

### 4.0 참고 시트에서 가져오는 설계 원칙
- **트랙(감시 분야)과 공고(실제 공고)를 분리**한다. 트랙은 "무엇을 찾을지", 공고는 "공식 페이지로 확인된 실제 건"이다.
- **공고ID 기준 중복 방지**: 공식 게시글 ID(예: `SBIZ-10308`, `KSA-1590129`)를 쓰고, 없으면 URL 해시로 대체한다. 같은 사업의 상반기/하반기(차수)는 별개 행으로 분리한다.
- **사람이 입력하는 열과 자동 열을 분리**: 자동 수집은 지원여부·지원일·결과·후속조치를 절대 덮어쓰지 않는다.
- **'공고별 확인' 같은 미확인 표시**를 허용하고, 공식 공고문 확인 전에는 확정값으로 보지 않는다.
- **개인지원 가능 여부**(개인/법인 용역/조건부)를 필드로 둔다. 법인 용역만 가능한 공고는 후보에서 걸러낼 수 있어야 한다.
- 기관 우선순위(★), 적합성 등급(A/B/C), 마감 D-Day, 이모지 상태(🟢🟡🔴)를 그대로 사용한다.

### 4.1 탭 목록

| 탭 | 역할 | 참고 시트 대응 | 입력 주체 |
|---|---|---|---|
| `00_모니터링트랙` | 감시 분야, 검색 키워드, 마지막 검색일, 최근 발견 공고ID | 동일 | 사람 + 자동(검색일/발견ID) |
| `01_전체관리` | 실제 공고 마스터 | 동일 | 자동 수집 + 사람 보완 |
| `02_분류체계` | 대분류/세부분야/기관군/검색 키워드 | 동일 | 사람 |
| `03_지원관리` | 지원 파이프라인 뷰 | 동일 | 사람 (일부 수식 연동) |
| `04_기관목록` | 모니터링 기관, ★ 우선순위, 대표 URL | 동일 | 사람 |
| `05_사용가이드` | 사용 규칙 | 동일 | 사람 |
| `06_키워드필터` | 포함/제외 키워드, 가중치 | **신규** | 사람 |
| `07_수집원` | RSS/API/HTML/메일 소스 등록, 실행 결과 | **신규** | 사람 + 자동 |
| `08_이력` | 상태/지원/결과 변경 로그 | **신규** | 자동 |
| `09_설정` | 알림 이메일·시각·임박 기준일·최소 점수 | **신규** | 사람 |
| `10_로그` | 수집 실행 로그 | **신규** | 자동 |

### 4.2 `01_전체관리` 열 (참고 시트 32열 기준 + 자동화용 열)

참고 시트의 열을 그대로 쓰고, 끝에 자동화용 열만 추가한다. 이름·순서는 참고 시트와 같게 유지한다.

| 구분 | 열 |
|---|---|
| 식별 | 공고ID, 수집일, 상태(🟢진행중/🟡상시·모니터링/🔴마감) |
| 분류 | 유형(컨설턴트/강사/교육·자격), 세부분야 |
| 공고 정보 | 기관명, 사업명, 공고명, 모집형태, 개인지원, 주요역할, 자격요건, 우대사항, 모집시작일, 모집마감일, 활동지역, 보수/수당, 제출서류, 지원방법 |
| 판단 | 적합성(A/B/C), 적합근거, 보완사항 |
| **지원 (사람 입력, 자동 갱신 금지)** | 지원여부, 지원일, 결과, 후속조치 |
| 계산 | 마감D-Day (수식) |
| 출처 | 공식공고URL, 지원URL, 출처확인일, 비고, 대표소스URL(발견 출처) |
| **추가(자동화)** | 출처채널(알리미/나라장터/사람인…), 적합도점수, 매칭키워드, 최종수정 |

- **유형 확장**: 요구된 4개 공고 유형(정규/계약 강사 채용, 프리랜서 강의 의뢰, 컨설턴트 채용·프로젝트, 정부/공공 강사·멘토)은 `유형`(강사/컨설턴트/교육·자격)과 별도로 `모집형태`(전문가 인력풀/채용/프로젝트 용역/강의 의뢰)로 구분한다. 추가 열 `공고유형`(채용-강사/의뢰-강의/채용-컨설턴트/공공-강사멘토)을 두고 드롭다운으로 관리한다.
- 지원여부 드롭다운: 미검토 / 지원검토 / 준비중 / 지원완료 / 지원불가 / 보류 / **패스**(사유 필수)
- 결과 드롭다운: 결과대기 / 서류합격 / 면접예정 / 최종합격 / 불합격 / 선정 / 탈락 / 포기
- `마감D-Day`는 `D-27`/`D+2`/`상시` 형식 (참고 시트와 동일). 날짜 기준 정렬이 필요하면 숫자 보조 열을 숨김 열로 둔다.
- 신규 자동 수집 건은 **지원여부 = 미검토**로 들어간다 (별도 '신규' 상태를 두지 않음).

### 4.3 상태·지원 흐름

```
[자동 수집] 미검토 → 지원검토 → 준비중 → 지원완료 → 결과대기 → 서류합격 → 면접예정 → 최종합격/선정
                │         │                       └────────────────────────→ 불합격/탈락
                ├─ 지원불가(자격 미달·법인 용역만)  └─ 포기
                └─ 패스(사유) / 보류(사유)
상태(🟢🟡🔴): 마감일 경과 시 자동으로 🔴 마감 (지원여부가 지원완료 이후면 건드리지 않음)
```

- `03_지원관리`는 `01_전체관리`에서 **지원검토 이상**인 건만 보여주는 뷰이며 `현재단계`·`준비자료`를 추가로 입력한다. `FILTER`/`QUERY` 수식으로 연동한다(참고 시트는 수동 복사 형태 → 수식화).

### 4.4 `00_모니터링트랙`
참고 시트 열을 유지한다: 트랙ID, 유형, 세부분야, 대상 기관, 주요역할, 검색 키워드, 예상 적합성, 적합근거, 마지막 검색일, 최근 발견 공고ID, 최근 발견 출처URL, 메모.
- `검색 키워드`는 알리미 RSS/API 검색 쿼리의 입력으로 쓰인다 (쉼표 구분 → 각각 검색).
- 자동 수집이 실제 공고를 발견하면 `01`에 새 행을 만들고 이 탭의 `마지막 검색일`·`최근 발견 공고ID`만 갱신한다.

### 4.5 `06_키워드필터`
| 열 | 설명 |
|---|---|
| 구분 | `포함` / `제외` |
| 키워드 | 예: AI, AX, 생성형AI, 업무자동화 / 아르바이트, 수강생 모집 |
| 가중치 | 포함 키워드 점수(기본 1, 제목 일치 시 ×2) |
| 사용 | TRUE/FALSE |

- 기본 포함 키워드는 `02_분류체계`의 `핵심 검색 키워드`와 `00_모니터링트랙`의 `검색 키워드`에서 자동으로 가져오고, 이 탭은 추가·제외·가중치 조정용이다.
- **제외 키워드가 하나라도 있으면 폐기(로그만 기록)**, 포함 점수 합이 `09_설정.최소점수` 이상이면 등록한다.
- **수강생(교육생) 모집 공고는 제외**: 참고 시트에서 "소상공인 AI마케팅 교육은 수강생 모집만 확인"처럼 강사 모집이 아닌 건이 섞이므로, `수강생 모집`, `교육생 모집`, `참가기업 모집`, `도입기업 모집` 등을 기본 제외어로 두고 `강사`, `전문가`, `컨설턴트`, `멘토`, `인력풀` 등을 필수 단서 키워드로 사용하는 옵션(`필수 포함 1개 이상`)을 둔다.

### 4.6 `07_수집원` / `09_설정` / `08_이력` / `10_로그`
- `07_수집원`: 이름, 종류(`rss`/`api`/`html`/`mail`), URL·쿼리, 사용, 마지막 실행, 결과. `04_기관목록`의 `대표소스URL`도 `html` 소스 후보로 사용 가능하게 한다(기관 게시판 변경 감지).
- `09_설정`: 알림 이메일, 발송 시각, 최소 점수, 임박 기준일(기본 3·1), 수집 주기, 마감 후 보관일.
- `08_이력`: `일시 | 공고ID | 공고명 | 필드 | 이전 | 이후` (지원여부·지원일·결과·마감일 변경 시 `onEdit`이 append).
- `10_로그`: 소스별 신규/중복/제외/오류 건수와 오류 메시지.

### 4.7 `04_기관목록` 활용
기관명, 기관군, 주요 기회분야, 우선 모니터링(★), 비고, 대표소스URL을 유지한다. 자동 수집 시 `기관명` 매칭으로 ★ 기관 공고를 적합도에 가산하고, 이메일 요약에서 ★★★ 기관 공고를 상단에 노출한다.

## 5. 자동화 동작

| 함수 | 트리거 | 동작 |
|---|---|---|
| `collect()` | 시간 기반, 하루 2회(예: 08시·18시) | 활성 소스 실행 → 정규화 → 필터/점수 → ID로 중복 제거 → `01_전체관리` 하단 추가, `00_모니터링트랙` 검색일·발견ID 갱신 |
| `dailyDigest()` | 시간 기반, 매일 08:30 | Gmail 요약 발송 |
| `expireOld()` | `dailyDigest` 내부 | 마감 경과 건 상태를 `마감`으로 |
| `onEdit(e)` | 설치형 편집 트리거 | 이력 기록, 최종 수정 갱신, 사유 필수 안내, URL 수동 입력 보강 |
| `onOpen()` | 단순 트리거 | 메뉴 `구인트래커` → 지금 수집 / 다이제스트 발송 / 트리거 설치 |

### 일일 이메일 구성
1. 신규 공고 (★★★ 기관·적합도 높은 순, 링크 포함)
2. 마감 임박: 지원 전(`미검토`·`지원검토`·`준비중`) D-3/D-1/당일
3. 예정 일정: 면접·결과 발표 (`다음 일정`이 3일 이내)
4. 수집 오류가 있으면 한 줄 경고

### 중복 제거
공식 게시글 ID가 있으면 `기관약어-게시글번호`(예: `SBIZ-10308`)를, 없으면 정규화 URL(쿼리 추적 파라미터·프래그먼트 제거)의 해시를 공고ID로 사용. 같은 사업의 차수(상·하반기, 2차)는 별개 공고로 취급. 같은 공고가 여러 소스에서 들어오면 최초 건 유지, `출처`에 병합 표기.

## 6. 저장소 구조

```
search-job/
├─ docs/DESIGN.md           # 이 문서
├─ docs/SHEET_TEMPLATE.md   # 탭·헤더·드롭다운·서식 상세 (참고 시트 00~05 + 신규 06~10)
├─ apps-script/
│  ├─ appsscript.json       # 시간대 Asia/Seoul, OAuth 스코프
│  ├─ Config.gs             # 시트명/열 인덱스 상수, 설정 로더
│  ├─ Main.gs               # collect, dailyDigest, onOpen, 트리거 설치
│  ├─ Filter.gs             # 키워드 필터·점수
│  ├─ Dedupe.gs             # URL 정규화·해시
│  ├─ Sheet.gs              # 읽기/쓰기, 이력, 상태 전환
│  ├─ Notify.gs             # Gmail 다이제스트
```

## 7. 구현 단계

1. **MVP**: 시트 템플릿 + 수동 입력 + 상태/이력 + D-day 서식 + 일일 Gmail 다이제스트
2. 키워드 필터/점수 + 알리미 RSS 수집 + 중복 제거
3. 공공 OpenAPI(나라장터/K-Startup) 어댑터
4. 사람인/잡코리아/원티드, 프리랜서 플랫폼 어댑터
5. 대시보드·로그·오류 알림 정리

## 8. 보안·운영 고려

- 시트 ID, API 키는 **스크립트 속성(Script Properties)** 에 저장하고 저장소에 커밋하지 않는다. `.clasp.json`은 `.gitignore`.
- Apps Script 일일 실행 시간·`UrlFetchApp` 호출 할당량 내에서 소스당 호출 수를 제한하고, 실행 시간 초과를 대비해 소스별로 try/catch 후 다음 소스로 진행.
- 사이트 이용약관·robots 정책을 존중: 차단되는 HTML 스크래핑 소스는 기본 `사용=FALSE`로 두고 RSS/알림메일 대체 경로를 안내.
- 개인정보(연락처)는 시트 공유 범위를 본인으로 제한.

## 9. 미결정 사항 (확인 필요)

- 사용할 사람인/잡코리아/원티드의 구체 연동 방식(공식 API 신청 가능 여부, 알림 메일 사용 여부)
- 프리랜서 플랫폼 중 실제 확인하는 곳 목록
- 포함/제외 키워드 초기 목록과 최소 점수
- 이메일 발송 시각, 마감 임박 기준일(기본 D-3, D-1)
- 참고 시트는 그대로 쓰지 않고 구조만 참고하기로 함 → 새 시트를 만들지(권장: 참고 시트 복사 후 06~10 탭 추가), 비어 있는 새 시트에 제가 생성할지
- 참고 시트는 주 1회(월 08:49) 수동성 자동 루틴으로 운영 중 → 본 시스템은 하루 2회 수집으로 대체할지, 주 1회로 줄일지
- 개인 지원 불가(법인 용역) 공고를 수집 단계에서 제외할지, `지원불가`로 표시만 할지
